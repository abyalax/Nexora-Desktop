# 0009 — Stay on Rust edition 2021 until after M7

Status: accepted **and completed** · Scope: `Cargo.toml`, `rustfmt.toml`, `AGENTS.md` §4, `rust-toolchain.toml` (BASE-05, BASE-06)

## Context

`AGENTS.md` said edition 2024, `Cargo.toml` says 2021 and `rustfmt.toml` said 2024. The three disagreed. The platform
code is Windows-only and cannot be exercised by the Linux CI job, so an edition migration (unsafe-extern, tail-expression
temporaries, `impl Trait` capture rules) could not be verified there.

## Decision

* Stay on **2021**. `Cargo.toml` is the source of truth; `rustfmt.toml` now says 2021 too (`style_edition` stays 2024, so
  formatting is unchanged and `cargo fmt --check` still passes).
* `AGENTS.md` §4 is amended to match.
* Revisit in M7 (hardening), when a Windows runner and the recovery tests exist: run `cargo fix --edition`, then flip.

## Implementation (M7, 2026-11-27)

* Migration completed on Windows 11 with `cargo fix --edition --allow-dirty`.
* All crate `Cargo.toml` files updated to edition 2024.
* Workspace `Cargo.toml` updated to edition 2024.
* `rustfmt.toml` updated to edition 2024.
* `AGENTS.md` §4 updated to reflect edition 2024.
* 52 warnings generated (tail-expr-drop-order changes), all in Windows COM/WinRT code - these are harmless per the compiler notes.

## Consequences

* Code now uses Rust 2024 edition features.
* Toolchain remains pinned in `rust-toolchain.toml` (1.85.0, which supports 2024).
